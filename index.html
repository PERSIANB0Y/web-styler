INSTALLATION

One file, one line

Copy auto-theme.js next to your HTML file and reference it from the <head>: 

<script src="auto-theme.js"></script>

That's it. A floating theme toggle appears bottom-right, the design system is injected, and every element on the page gets classified and styled automatically.

Placement matters

  • Put the script inside <head> so the theme is applied before first paint — no flash of unstyled content.
  • It is safe to move to the end of <body> — the script waits for DOMContentLoaded.
  • No build step, no module loader, no type="module" needed. It's a classic IIFE that attaches to window.AutoTheme.
QUICK START

The smallest possible page

Write ordinary, semantic HTML. The library figures out the rest — sticky header, responsive grid, card shapes, hero layout, eyebrow labels, and so on. 

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My site</title>
    <script src="auto-theme.js"></script>
</head>
<body>

    <header>
        <strong>My Site</strong>
        <nav>
            <a href="#home">Home</a>
            <a href="#about">About</a>
        </nav>
    </header>

    <main>
        <section id="home">
            <h1>Hello, world</h1>
            <p>This page has zero CSS files.</p>
        </section>

        <section id="about">
            <span>ABOUT</span>
            <h2>A little about me</h2>

            <div>
                <article>Card one</article>
                <article>Card two</article>
                <article>Card three</article>
            </div>
        </section>
    </main>

    <footer>
        <small>© 2026</small>
    </footer>

</body>
</html>

Open it in a browser — the layout, colors, hero, cards, grid, eyebrow, and footer are all automatic.

HOW IT WORKS

What each tag becomes

The library scans your DOM once, tags every relevant element with a data-ui attribute, and lets the injected CSS take over. Nothing about your markup is rewritten — attributes are added, never removed.

You write Tagged as Effect
header data-ui="header" Sticky frosted-glass bar
nav data-ui="nav" Horizontal menu
nav a, header a data-ui="nav-link" Muted link with red hover
main > section data-ui="section" Centered container + padding
First section containing h1 data-ui="hero" Big centered hero block
Short ALL-CAPS element before h1/h2 data-ui="eyebrow" Small red uppercase label
article, figure, aside, blockquote, details data-ui="card" Rounded bordered card
Wrapper div/ul whose only children are cards data-ui="grid" Responsive auto-fit grid
button, input[type=submit], a[role="button"] data-ui="button" Pill button
a[download] data-ui="button" + data-variant="secondary" Outlined pill button
footer data-ui="footer" Bordered footer row
dialog, [role="dialog"] data-ui="modal" Rounded modal + backdrop blur
auto-injected data-ui="ambient" Background radial gradient
auto-injected data-ui="noise" SVG noise texture overlay
auto-injected data-ui="theme-toggle" Floating dark/light switch

Opting out or overriding

Already tagged something manually? The classifier never overwrites an existing data-ui attribute — so you can force a specific role: 

<!-- Always a card, even if it's a div -->
<div data-ui="card">Custom card</div>

<!-- Force a secondary button -->
<button data-variant="secondary">Cancel</button>

Want to exclude an element from all styling? Use data-ui="none" — or just wrap it in a shadow root.

REFERENCE

JavaScript API

Everything lives on window.AutoTheme. All methods are synchronous and safe to call at any time.

Methods

Method What it does
AutoTheme.apply() Re-apply the current theme (after manual changes).
AutoTheme.refresh() Re-scan the DOM and tag new elements.
AutoTheme.set('dark') Force a specific theme: "dark", "light", or "system".
AutoTheme.toggle() Flip between dark and light.
AutoTheme.mode Getter — the current mode ("system" by default).

Examples

// Force light mode and remember it
AutoTheme.set("light");

// Follow the OS again
AutoTheme.set("system");

// Toggle from a custom button
document.querySelector("#my-btn").onclick = () => AutoTheme.toggle();

// Re-scan after injecting HTML
container.innerHTML = "<article>New card</article>";
AutoTheme.refresh();

// Read the mode
console.log(AutoTheme.mode); // "system" | "dark" | "light"

Framework integration

In React, Vue, Svelte, or any framework that swaps DOM nodes, call AutoTheme.refresh() after mount or route change. A MutationObserver already handles most cases — but calling explicitly is cheap and reliable. 

// React
useEffect(() => {
    window.AutoTheme?.refresh();
}, [route]);

// Vue
onMounted(() => window.AutoTheme?.refresh());

// Svelte
onMount(() => window.AutoTheme?.refresh());
CUSTOMIZATION

Make it yours

Recolor everything

The entire palette flows from CSS custom properties. Override any of them — the whole UI follows, including the injected modal, form controls, and hover states. 

<style>
:root {
    --red:        #00d4ff;   /* accent */
    --red-light:  #33e0ff;   /* hover accent */
    --red-dark:   #0088aa;

    --bg:         #05070a;
    --surface:    #0e1117;
    --text:       #e6f2ff;

    --radius:     24px;      /* bigger cards */
    --container:  1200px;    /* wider page */
}

html[data-theme="light"] {
    --bg:      #f0f9ff;
    --text:    #081018;
    --red:     #0088aa;
    --red-light: #00b4d8;
}
</style>

Change the storage key

By default the theme preference is stored under auto-theme in localStorage. To avoid collisions with other scripts on the same origin, override the key before loading the file: 

<script>window.AUTO_THEME_KEY = "my-site-theme";</script>
<script src="auto-theme.js"></script>

Note: this requires a one-line change in auto-theme.js if you want the value read from window.AUTO_THEME_KEY. The default STORAGE_KEY constant is at the top of the file.

Disable the floating toggle

If you'd rather call AutoTheme.toggle() from your own UI, remove the auto-created button: 

document.addEventListener("DOMContentLoaded", () => {
    document.querySelector('[data-ui="theme-toggle"]')?.remove();
});

Playing nice with existing CSS

The injected stylesheet uses low specificity — one type selector or one [data-ui] attribute. Your own rules like .my-button { … } will win without !important as long as they load after auto-theme.js. If they load before, add !important or increase specificity with a parent selector.

Why is there no styles.css file?

Because auto-theme.js is the stylesheet — it injects a <style> block on load. You still get to customize everything through CSS variables.

FAQ

Questions you might ask

Does it work without JavaScript enabled?

No styling is applied at all — the page falls back to the browser's default rendering. Everything lives inside the injected <style>.

Can I use it with Tailwind, Bootstrap, etc.?

Yes. Both libraries manipulate the DOM without removing your data-ui attributes. To keep the libraries from fighting, either load auto-theme.js after the framework, or disable one of them per-page.

Will it break my existing classes and IDs?

Never. It only adds data-ui attributes. Your IDs, classes, event handlers, and form values are untouched.

What about accessibility?

Semantic tags are preserved, focus styles come from :focus-visible, the theme toggle has an aria-label, ambient and noise layers are aria-hidden, and it respects prefers-reduced-motion and prefers-color-scheme.

Browser support?

Modern evergreen browsers (Chrome, Edge, Firefox, Safari 15+). Uses color-mix(), :focus-visible, and dialog. On older browsers it degrades gracefully — you still get the layout and base colors, just without some of the polish.

How big is the injected CSS?

About 12 KB unminified, ~3 KB gzipped. The entire library is a single file, so there are no extra network requests.
